La idea central

Tres piezas, tres responsabilidades

Modelo

Sabe

Los datos y las reglas del negocio.

No sabe

Que existe una pantalla.

Vista

Sabe

Cómo mostrar el estado y qué hizo el usuario.

No sabe

Ninguna regla de negocio.

Controlador

Sabe

Traducir lo que hace el usuario en órdenes.

No sabe

Dibujar ni calcular.

En Notas del semestre: el Modelo guarda pesos y notas y sabe si aprobó; la Vista dibuja la tabla y el resumen; el Controlador recibe «agregar», «calificar» o «eliminar».

Paso 1

El usuario actúa

Paso 2 · Controlador

Traduce

Convierte el texto del formulario en una orden para el Modelo.

Paso 3 · Modelo

Decide

Valida las reglas, cambia su estado y avisa que cambió.

Paso 4 · Vista

Se redibuja

Lee el Modelo y muestra la fila nueva.

Si el Modelo rechaza la orden, lanza un error de reglas: el Controlador lo atrapa y le pide a la Vista que muestre el mensaje.

Un patrón dentro del patrón

El Modelo avisa sin saber a quién

NotasModelo

suscribir(fn) {

  this.#suscriptores.add(fn);

  return () => this.#suscriptores.delete(fn);

}

 

#cambio() {

  this.#almacen.guardar(this.evaluaciones);

  for (const fn of this.#suscriptores) fn();

}

1 · Se suscriben

El Modelo guarda una lista de funciones.

2 · Algo cambia

Recorre la lista y las llama, una por una.

3 · No sabe quién escucha

Una tabla, un termómetro o una prueba.

Es el patrón de diseño Observer, que MVC usa por dentro.

Cuando MVC sale mal

Cuatro olores de un MVC mal hecho

Controlador gordo

Síntoma

Valida y calcula; el Modelo queda casi vacío.

Arreglo

Mover cada regla al Modelo.

Lógica en la Vista

Síntoma

Un if (nota >= 3) dentro del código de la pantalla.

Arreglo

La Vista le pregunta al Modelo; no decide.

Modelo que toca la pantalla

Síntoma

alert(), document o innerHTML dentro del Modelo.

Arreglo

El Modelo lanza errores; otros los muestran.

Modelo anémico

Síntoma

Solo datos y getters; las reglas viven en otro lado.

Arreglo

Que el Modelo proteja sus propias reglas.

En el laboratorio, las pruebas de arquitectura detectan los dos del medio.

La balanza

Beneficios y costos

Beneficios

  • Probar el Modelo sin pantalla
  • Varias vistas del mismo Modelo
  • Trabajo en paralelo: una pieza por persona
  • Cambios localizados

Costos

  • Más archivos y más indirección
  • Exagerado para una app de 100 líneas
  • Fácil mezclar roles: «¿esto dónde va?»
  • Hay que aprender el vocabulario

MVC no es un fin: es una forma de pagar menos cada vez que hay que cambiar.
